## 1. Назначение и бизнес-контекст

Платформа **«АВТОСКЛАД-ИИ»** разработана для автоматизации, аудита и монетизации товарных запасов оптово-розничных сетей автозапчастей (грузовой и легковой сегмент: **ГАЗ, УАЗ, ВАЗ, КАМАЗ, ЗМЗ, УМЗ**).

### Ключевые проблемы отрасли, решаемые системой:
1. **«Грязные» выгрузки 1С:** Ведомости остатков с пустыми шапками, нерегулярными названиями колонок, строками «Итого», иерархическими группами и кодировками (`cp1251`, `cp866`, `utf-8-sig`).
2. **Гаражный сленг и хаос номенклатуры:** Одинаковые детали заведены в 1С под 3–7 разными именами (например: `«Редуктор з/м 3302»`, `«Главная пара соболь»`, `«Дифференциал ГАЗель бизнес»`, с опечатками и латиницей вместо кириллицы).
3. **Замороженный капитал (Мертвый склад):** До 30–45% оборотных средств компаний заморожено в позициях без движения свыше 180 дней.
4. **Откаты закупщиков и перезакуп:** Закупка неликвида при наличии запасов на годы вперед и одновременный дефицит ходовых позиций (out-of-stock).
5. **Галлюцинации чат-ботов:** Риск того, что ИИ-продавец пообещает клиенту запчасть, которой нет на складе, или назовет неверную цену.

## 3. Детальное описание компонентов

### 3.0. `inventory_guard.py` (Enterprise Input Hardening)
- **Устойчивость к форматам:** Читает Excel (`openpyxl`), CSV, TSV.
- **Поддержка кодировок:** Автоматически перебирает `utf-8-sig`, `utf-8`, `cp1251`, `cp866`.
- **Эвристический поиск шапки:** Сканирует первые 25 строк файла на наличие семантических маркеров (`наименование`, `номенклатура`, `товар`, `остаток`, `артикул`).
- **Маппинг колонок:**
  - Приоритет отдается колонке `Конечный остаток` (а не `Начальный остаток` или `Остаток на начало`).
  - При наличии нескольких складов (`Остаток Магазин 1`, `Остаток Склад 2`) автоматически суммирует остатки.
  - Извлечение продаж идет из колонки `Расход` или `Продажи`.
- **Очистка данных:** Отсекает строки с префиксами `ИТОГО`, `ВСЕГО`, пустые строки, технические заголовки разделов без цен и остатков.
- **Безопасность:**
  - Предотвращение CSV Formula Injection (экранирует лидирующие `=, +, -, @`).
  - Предотвращение Path Traversal при передаче путей файлов.
  - Строгая валидация числовых значений (замена запятых на точки, удаление неразрывных пробелов `\xa0`).

### 3.1. Модуль 1 — `auditor.py` (Аудит 1С и расчет неликвида)
- **Функции:**
  - `audit_inventory(filepath)`: Выполняет комплексный аудит файла остатков.
  - Расчет ABC-категорий (по вкладу в оборот/выручку) и XYZ-категорий (по регулярности спроса).
  - Выявление висяков: фильтр по дням без движения (> 180 дней) и отрицательному тренду.
  - Расчет дублированных позиций номенклатуры с оценкой замороженных денег в дублях.
  - Генерация JSON-сводки (`audit_summary.json`) и автономного адаптивного отчета (`audit_report.html`).

### 3.2. Модуль 2 — `matcher.py` (3-Уровневый каскадный ИИ-Матчер)
- **Каскад матчинга:**
  - **Уровень 1 (OEM Match):** Нормализация артикула (удаление спецсимволов, пробелов, приведение латиницы/кириллицы) -> мгновенный поиск в эталоне.
  - **Уровень 2 (Cross-Catalog Index):** Поиск по таблице кросс-номеров `master_crosses` в SQLite `master_catalog.db`.
  - **Уровень 3 (Semantic & Fuzzy Fallback):** Поиск с использованием метрик Левенштейна (`rapidfuzz.fuzz.token_sort_ratio`) с порогом сходства, с опциональным обращением к LLM (OpenAI API) при наличии ключа.
- **Эталонный каталог:**
  - `seed_master_catalog.py`: Инициализация SQLite базы `master_catalog.db` с 20 ключевыми узлами ГАЗ/УАЗ (КПП, ГБЦ, редукторы, карданы, сцепления, радиаторы, генераторы) и кросс-таблицами аналогов (Dymos, УМЗ, ЗМЗ, БАТЭ, Пекар).
  - Генерация отчета сопоставления (`matching_report.html`).

### 3.3. Модуль 3 — `feed_generator.py` (Экспорт фидов Авито и Дром)
- **Avito XML Feed (`avito_feed.xml`):**
  - Полное соответствие XML-схеме Авито (раздел «Запчасти и аксессуары»).
  - Теги: `<Id>`, `<Title>`, `<Description>`, `<Price>`, `<Availability>`, `<Condition>`, `<OEM>`, `<Brand>`, `<Model>`, `<Images>`.
  - Защита от XML Injection через безопасную сборку элементов (`xml.etree.ElementTree`).
- **Drom CSV Feed (`drom_feed.csv`):**
  - Разделитель `;`, кодировка `utf-8-sig` (для корректного открытия в Excel).
  - Поля: Артикул, Наименование, Марка, Модель, Цена, Наличие, Состояние, Номер детали.
- **Интерактивная витрина (`feeds_preview.html`):** Веб-каталог с карточками товаров, подсветкой маржинальности и статуса выгрузки.

### 3.4. Модуль 4 — `ai_sales_bot.py` (Zero-Hallucination ИИ-Продавец)
- **Архитектура RAG + Tool Calling:**
  - Бот не выдумывает остатки, а запрашивает инвентарь через функцию `search_inventory(query, engine_or_model)`.
  - Поиск идет строго по позициям с `total_stock > 0`.
  - Если позиция найдена, но остаток 0 — бот честно сообщает статус `OUT_OF_STOCK` и предлагает привезти под заказ на следующий день к 10:00.
- **Функция `create_reservation(client_name, client_phone, master_id, quantity, comment)`:**
  - Бронирование детали в базе данных SQLite.
  - Транзакционный контекст с защитой от race condition: `with conn:` и явное закрытие соединений.
  - Генерация уникального ID резерва: `RES-YYYYMMDDHHMMSSfff-ID-HASH`.
  - Валидация телефона клиента и проверка на повторное бронирование.
- **Веб-симулятор (`bot_simulator.html`):** Полноценный интерфейс чата с предустановленными сценариями тестирования (поиск по артикулу, поиск по сленгу, проверка отсутствующей детали, бронирование с подтверждением).

### 3.5. Модуль 5 — `owner_radar.py` (Недельный радар собственника)
- **Сравнение недельных слепков (`week_prev.xlsx` vs `week_curr.xlsx`):**
  - **Разморозка неликвида:** Фиксация позиций из категории неликвида, проданных за неделю через Авито/Дром (возврат живых денег в кассу).
  - **Аномальный перезакуп (Анти-откат):** Выявление позиций, по которым при наличии запаса > 300 дней закупщик оформил новый приход.
  - **Упущенная выручка (Deficit Alert):** Позиции с нулевым остатком при высоком стабильном спросе.
  - **Интегральные показатели:** Динамика замороженного капитала, сумма размороженных средств.
- **Генерация выходов:**
  - `telegram_digest.txt` — готовое текстовое сообщение для отправки директору в Telegram с эмодзи-индикаторами и сводкой.
  - `owner_radar.html` — интерактивная панель с графиками, бейджами и карточками аномалий.

## 4. База данных SQLite (`master_catalog.db`)

База данных содержит 3 основные таблицы:
```sql
-- Эталонный каталог запчастей
CREATE TABLE master_items (
    master_id TEXT PRIMARY KEY,
    canonical_title TEXT NOT NULL,
    oem_number TEXT NOT NULL,
    brand TEXT NOT NULL,
    applicability TEXT,
    category TEXT,
    base_retail_price REAL,
    min_price REAL
);

-- Таблица кросс-номеров и аналогов
CREATE TABLE master_crosses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    master_id TEXT NOT NULL,
    cross_oem TEXT NOT NULL,
    cross_brand TEXT,
    note TEXT,
    FOREIGN KEY(master_id) REFERENCES master_items(master_id)
);

-- Таблица оперативных клиентских резервов
CREATE TABLE reservations (
    res_id TEXT PRIMARY KEY,
    client_name TEXT NOT NULL,
    client_phone TEXT NOT NULL,
    master_id TEXT NOT NULL,
    quantity INTEGER NOT NULL,
    status TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    comment TEXT,
    FOREIGN KEY(master_id) REFERENCES master_items(master_id)
);
```
